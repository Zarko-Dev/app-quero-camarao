# Expo SDK 53 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Expo SDK 52 → 53 (React Native 0.76.9 → 0.77.x) to fix Android 16KB page alignment requirement enforced by Google Play.

**Architecture:** Branch-isolated upgrade with 7 commit groups (one per dep group). Each group committed independently for easy bisect. Old Architecture (`newArchEnabled=false`) maintained throughout — 16KB fix comes from RN 0.77 pre-built binaries, not new arch. NDK 27.1.12297006 unchanged.

**Tech Stack:** Expo SDK 53, React Native 0.77.x, EAS Build, yarn, Android NDK 27, iOS + Android.

---

If it fails with a plugin error — read the error carefully. The plugin name is in the stack trace. Fix the plugin or update the package that ships it.

- [ ] **Step 2: Verify gradle.properties unchanged**

Open `android/gradle.properties`. Confirm these values are still present:

```properties
newArchEnabled=false
hermesEnabled=true
ndkVersion=27.1.12297006
```
If `newArchEnabled` was reset to `true` by prebuild, set it back to `false`.

- [ ] **Step 3: Verify sentry.gradle still in app/build.gradle**

Open `android/app/build.gradle`. Confirm the Sentry apply line is still present (prebuild regenerates this file from the plugin):

```groovy
apply from: new File(["node", "--print", "require('path').dirname(require.resolve('@sentry/react-native/package.json'))"].execute().text.trim(), "sentry.gradle")
```
If missing — the Sentry Expo plugin should have re-added it. If not, add it back manually and note the issue.

## Task 8: EAS build + validation

**Files:** none (build only)

- [ ] **Step 1: Trigger Android dev build**

```bash
eas build --profile development --platform android
```
Watch the build log. Common failure points:
- Gradle sync error → likely a dep version conflict, check error and fix in package.json
- Compile error in a native module → check that module's SDK 53 support
- Hermes compile error → unlikely with expo-managed hermes

- [ ] **Step 2: Trigger iOS dev build**

```bash
eas build --profile development --platform ios
```
Watch for pod install errors — if a pod can't resolve for RN 0.77, that native module needs updating.

- [ ] **Step 3: If Android build passes — check 16KB compliance**

Download the `.apk` from EAS dashboard. Upload to Google Play Console internal testing track or use the Pre-launch report to verify 16KB compliance. All `libreactnative.so`, `libhermes.so`, etc. should now pass.

- [ ] **Step 4: Smoke test on device**

Install dev build. Test core flows:
- Login
- Sales list / create sale
- Draws / raffle feature
- Navigation between main screens
- Push notifications (if testable in dev)

- [ ] **Step 5: Verify firebase still works**

`firebase@10.14.1` is a JS-only SDK — no native `.so` files from it directly. But it depends on Google Play Services via Gradle. If the Android build fails with a Firebase/Google Services error, bump it:

```bash
yarn add firebase@latest
```
Check `android/app/build.gradle` for `com.google.gms:google-services` version — should be `4.4.x` or newer.

- [ ] **Step 6: Handle libbarhopper_v3.so (if still flagged)**

If Google Play still flags `libbarhopper_v3.so` after the upgrade:

```bash
# Find which package ships it
find node_modules -name "libbarhopper_v3.so" 2>/dev/null
```
Note the package. Open an issue on that package's repo. As a short-term mitigation, check if the barcode feature can be disabled or the dependency removed.

- [ ] **Step 7: Merge to main**

Only after both builds pass and smoke test is clean:

```bash
git checkout main
git merge feat/expo-sdk-53
git push origin main
```
